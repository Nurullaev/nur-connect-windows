# Первая сборка Nur Connect для Windows

Версия: **0.1.0-pre.1+8**. Первый предварительный выпуск для Windows x64.
Промежуточная +1 и итоговая версия собраны; окно приложения открыто на Windows.

## Среда

Windows 11 Pro ARM64 в Parallels. Целевой первый пакет — Windows x64.
Flutter 3.47.6 (`5fc346839b5d0eef006ed8404392afb4dfae428d`), Dart 3.13.5,
Go 1.27.1, Rust 1.99.0 для native API, Visual Studio Build Tools 2022
17.14.45 / MSVC 14.44 / Windows SDK 10.0.26100.0, C++ ATL (нужен
плагину уведомлений Windows), Inno Setup 6.7.4.

Анализатор: `flutter analyze --no-pub --no-fatal-infos` — **No issues found**.
Целевые проверки импорта, профиля/HWID, запуска, главной, серверов, настроек,
идентификаторов, About и обновлений прошли после исправлений. Основной прогон:
349 успешных, 1 платформенный skip и 1 устаревшее ожидание ключа upstream;
после его исправления тесты манифеста — 26/26, итоговый повтор packaging +
manifest с проверкой архитектуры SDK — 56/56. Полный набор всех тестов upstream
не запускался. После добавления автопроверки версий анализатор повторно прошёл
без замечаний, а выбранные тесты обновлений, настроек, конфигурации и упаковки —
**294/294**. После визуальной проверки владельцем убраны повторный заголовок на главной,
квадратная подложка логотипа в About и крупная карточка автора форка.
Проверки обновлённых главной и About — **8/8**, включая узкое окно и крупный текст. «О программе» объединено с общим
списком переходов в настройках, сохраняя доступ в simple mode.

EXE и ZIP включают LICENSE.txt, NOTICE.md и SOURCE.txt. Проверены CRC ZIP,
архитектура основных PE-файлов, версия, хеш ядра относительно manifest.json и
SHA-256 sidecars. Пакеты подготовлены для предварительного выпуска; публичная
публикация ожидает окончания сравнения интерфейсов владельцем.

Для x64 нужен именно x64 Flutter/Dart SDK, даже на ARM64 Windows. Flutter
выбирает Windows target по ABI своего Dart и не поддерживает здесь параметр
`--target-platform`. Скрипт упаковки проверяет соответствие SDK и `--arch`,
чтобы случайно не назвать ARM64-сборку x64.

## Ограничения предварительного выпуска

- Приложение и установщик используют фирменный знак Nur Connect; функциональные
  статусные значки трея пока унаследованы. Источник — assets/branding/README.md.
- Authenticode и собственные ключи обновлений ещё не настроены. Provider-signed
  обновления без нашего доверенного ключа отклоняются.
- GitHub Actions форка отключены; upstream CI не используется для наших выпусков.
- Настоящая подписка, HWID, TUN/прокси и подключение к VPN требуют отдельной
  проверки на изолированном QA-профиле. Тесты используют фикстуры.
- Обычная Windows x64, установка рядом с FlClashX, автозапуск, сон/смена сети,
  обновление и удаление ещё не прошли полную приёмку.

## Выдача подписки

Windows UA: `Nur-Connect-Windows/v0.1.0-pre.1 core/v1.19.34 Platform/windows`.
В панели добавлено отдельное правило **Nur Connect Windows** после мобильных
клиентов, перед остальными Mihomo. Оно выбирает MIHOMO, не меняя HWID или шаблон
выдачи. Реальные пользовательские подписки для проверки этого этапа не запрашивались.

## Сравнение интерфейсов

21 ноября 2026 года владелец сравнил штатные экраны FlClashX с нашей версией
и выбрал упрощённый Nur Connect. В текущей версии снова используются
NurConnectDashboard, NurServersView и NurWindowsSettings. Повторное добавление
подписки, TUN/прокси и выбор режима убраны с заполненной главной; сетевые
параметры доступны в дополнительных настройках. Новая конфигурация по умолчанию
включает TUN и выключает системный прокси. Сохранённые настройки читаются
обычным путём, без принудительной миграции выбора пользователя.

Проверки восстановления штатной компоновки: панель/редактор/настройки и
сохранённый простой вариант — 32/32; список прокси — 12/12. После
устранения const-подсказок анализатор изменённых экранов — No issues found.

ARM-тесты и x64-сборка используют общие staging-пути Core/helper. Добавлено
отслеживание содержимого выходных файлов hook, а перед упаковкой проверяется
PE Machine каждого EXE/DLL. Пакет с примесью другой архитектуры отклоняется.
Промежуточная +6 была только локальным UI-preview на ARM Windows и не
предназначена для распространения на x64.

Единственное исключение PE-проверки — штатная самостоятельная x86-утилита
EnableLoopback.exe с закреплённым SHA-256 из upstream. Для приложения, Core,
Helper и всех DLL исключений нет.

Итоговая конфигурация +8: полный анализатор — No issues found, свежий режим
VPN/главная/настройки/серверы/PE и упаковка — 42/42 теста. Hook/cache — 16/16.
Сборка после ARM-тестов успешно прошла архитектурный guard и упаковку EXE/ZIP.
