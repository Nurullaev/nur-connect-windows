# План Nur Connect для Windows

Состояние на 21 ноября 2026 года. Windows — самостоятельный проект на базе
FlClashX; мобильные проекты не определяют его API и интерфейс.

## Реализовано

- [x] Свой форк с историей upstream и отдельные идентификаторы Windows: EXE,
      ядро/helper, служба, AppId/CLSID, AppData, lock, pipe и import URI.
- [x] Удаление установочной миграции поверх чужого FlClash/FlClashX.
- [x] Собственный репозиторий обновлений и имена артефактов; ключ upstream удалён.
- [x] Импорт HTTP/HTTPS/share/deep links с проверкой входа, busy/retry в том же
      окне, безопасными сообщениями и сохранением последнего файла при сбое сети.
- [x] Явный отказ по HWID сохраняет блокировку в профиле, останавливает активное
      подключение и запрещает запуск кэша до успешного обновления. Сетевой сбой
      сам по себе такой блокировки не создаёт.
- [x] Своя адаптивная главная: соединение, сервер, профиль, трафик и TUN/proxy.
- [x] Экран серверов: локальный поиск без изменения фильтра других страниц,
      группы, сортировка, выбранный узел и задержка без автоматической смены.
- [x] Настройки Windows через существующие persisted/managed providers:
      подключение, startup/background, язык/тема, профили/бэкап, логи, About;
      расширенные страницы доступны вне simple mode.
- [x] Сайт nurconnect.app в About, собственное описание и README; авторы и GPL
      сохранены, новые тексты RU/EN с английским fallback для других локалей.
- [x] Первый предварительный x64 выпуск 0.1.0-pre.1; установщик и переносимый ZIP.
- [x] Автопроверка новых версий, «Обновить / Позже», ручная проверка и SHA-256.
- [x] Фирменные иконки приложения и установщика из материалов Nur Connect.
- [x] Отдельный panel matcher после мобильных приложений, перед Mihomo Clients.
      UA `Nur-Connect-Windows` обходит широкое мобильное условие `NurConnect`;
      выдача MIHOMO, остальные правила/HWID/шаблон не менялись.
- [x] Подготовлена Windows VM, toolchain и выполнен анализатор без замечаний.

Состояние тестов и пакетов: [первая сборка](first-build.md).

## Следующие этапы

1. Приёмка первой предварительной версии с пользователями Windows x64.
2. Визуальная приёмка на Windows: узкое окно, крупный текст, импорт/ошибки,
   главный экран, выбор сервера, группы и настройки.
3. Отдельный QA-профиль: первая загрузка, HWID/лимит, обновление и кэш,
   подключение, TUN/proxy, отказ helper, гонки refresh/start/stop.
4. Установка рядом с FlClashX и stable/pre, обычный пользователь/UAC, трей,
   автозапуск, сон/смена сети, обновление/удаление и восстановление proxy.
5. Окончательный дизайн интерфейса, фирменные статусные значки трея и
   полная инвентаризация лицензий assets.
6. Собственный ключ Ed25519, Authenticode и Windows CI. Приватные ключи держать
   вне репозитория. Унаследованные workflows до адаптации не включать.
7. Расширить матрицу на чистую Windows 10/11 x64 и отдельную ARM64-сборку.
   При распространении прикладывать соответствующие исходники и инструкции.

## Проверки подписок

Parser не заменяет валидацию Core: YAML, age и конвертация share links остаются
в штатном потоке. Явный HWID refusal останавливает основную и резервную загрузки.
Staging/validate/rename и superseded guard сохранены. HTTP 403 сам по себе не
объявляется истечением подписки; пользовательские URL и core diagnostics не
выводятся в новом сообщении об ошибке. Полная проверка всех экспортов логов
на секреты — отдельная работа.
