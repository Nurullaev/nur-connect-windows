# План Nur Connect для Windows

Состояние на 21 ноября 2026 года. Windows — самостоятельный проект на базе
FlClashX; мобильные проекты не определяют его API и интерфейс.

## Реализовано

- [x] Свой форк с историей upstream и отдельные идентификаторы Windows: EXE,
      ядро/helper, служба, AppId/CLSID, AppData, lock, pipe и import URI.
- [x] Удаление установочной миграции поверх чужого FlClash/FlClashX.
- [x] Собственный репозиторий обновлений и имена артефактов; ключ upstream удалён.
- [x] Импорт HTTP/HTTPS/share/deep links с проверкой входа, busy/retry в том же
      окне, безопасными сообщениями и сохранением последнего файла при сбое сети.
- [x] Явный отказ по HWID сохраняет блокировку в профиле, останавливает активное
      подключение и запрещает запуск кэша до успешного обновления. Сетевой сбой
      сам по себе такой блокировки не создаёт.
- [x] Своя адаптивная главная: соединение, сервер, профиль, трафик и TUN/proxy.
- [x] Экран серверов: локальный поиск без изменения фильтра других страниц,
      группы, сортировка, выбранный узел и задержка без автоматической смены.
- [x] Настройки Windows через существующие persisted/managed providers:
      подключение, startup/background, язык/тема, профили/бэкап, логи, About;
      расширенные страницы доступны вне simple mode.
- [x] Сайт nurconnect.app в About, собственное описание и README; авторы и GPL
      сохранены, новые тексты RU/EN с английским fallback для других локалей.
- [x] Первый предварительный x64 выпуск 0.1.0-pre.1; установщик и переносимый ZIP.
- [x] Автопроверка новых версий, «Обновить / Позже», ручная проверка и SHA-256.
- [x] Фирменные иконки приложения и установщика из материалов Nur Connect.
- [x] Отдельный panel matcher после мобильных приложений, перед Mihomo Clients.
      UA `Nur-Connect-Windows` обходит широкое мобильное условие `NurConnect`;
      выдача MIHOMO, остальные правила/HWID/шаблон не менялись.
- [x] Подготовлена Windows VM, toolchain и выполнен анализатор без замечаний.
- [x] Чёрно-золотой дизайн по мобильному макету (0.1.0-pre.2): фиксированная
      фирменная схема вместо сгенерированной из голубого, большая кнопка питания с
      кольцом, таймер и скорость под ней, компактные строки серверов. Старый
      голубой цвет FlClashX в настройках переходит в фирменный, остальные цвета
      темы сохраняются.
- [x] Новые строки переведены на все семь языков; полный набор Flutter- и
      Go-тестов проходит на Windows (раньше 44 падения: устаревшие ожидания и
      тесты FlClashX, рассчитанные только на `/` в путях).
- [x] Живая проверка pre.2 с тестовыми пользователями панели: импорт, TUN,
      отказ HWID, истечение, уведомления, заголовки Remnawave.
- [x] Обычный выпуск 1.0.0: ссылки `bot-url` и `account-url`, состояние
      «Подписка закончилась» с «Продлить» вместо заглушек-серверов, окно лимита
      устройств с пояснением панели и поддержкой. Pre остаётся отдельной копией
      для тестов; на 1.0.0 переходят переустановкой.
- [x] 1.0.1: одно приложение для всех брендов панели — ключи Happ, которые уже
      шлют сквады: `sub-expire-button-link` (продление), `new-domain` (запасной
      домен), `banner-*` (промо под объявлением), название бренда вверху главной;
      ссылки `tg://resolve` открываются как t.me.
- [x] 1.0.2: свои значки трея (серый — отключено, цветной — подключено,
      точка — безопасный режим); описание выпуска в окне обновления без
      Markdown-разметки; после обновления программа запускается сама
      (`/SILENT … /RELAUNCH=1`, работает начиная с обновления из 1.0.2);
      издатель и папка данных — Nur Dev (`%APPDATA%\Nur Dev\NurConnectWindows`,
      старая папка `Nurullaev\…` переносится один раз); в списке программ
      название без «, версия …».
- [x] 1.0.3: раздельное туннелирование по программам (только выбранные через
      VPN или все, кроме выбранных; правила `PROCESS-NAME` перед правилами
      подписки, глобальный режим идёт в ядро как правила с `MATCH,GLOBAL`);
      на главной кнопка подключения наверху, объявление и промо под низкой
      карточкой профиля; в списке серверов больше нет групп-переключателей
      подписки. Описания серверов приходят из панели, когда правило подписки
      помечает приложение расширенным клиентом (`additionalExtendedClientsRegex`).
- [x] 1.0.4: на главной весь список серверов (узкое окно — под карточкой,
      широкое — своя колонка справа во всю высоту); профиль, промо и
      объявление в одной карточке; у профиля меню «⋯» с «Подробнее» и
      «Удалить»; в окне обновления фокус клавиатуры переходит на «Установить».
- [x] 1.0.5: Happ-флаги панели `hide-settings` и `hide-url` — без конфига
      (просмотр, правка, расширение, экспорт) и без ссылки подписки (копия,
      QR, редактор) у профилей, которым панель их прячет.
- [x] 1.0.6: ссылки провайдера на карточке профиля в порядке «Сайт → Бот →
      Подписка → Поддержка». «Сайт» (глобус) открывает кабинет из
      `account-url`, «Подписка» (ссылка) — страницу подписки из
      `profile-web-page-url`; отдельной кнопки «Аккаунт» больше нет. Как в
      Happ, при `sub-expire: 1` за 3 дня до конца и после него вместо промо
      в карточке «Подписка истекает через N д. / сегодня / истекла» и
      «Продлить» (`sub-expire-button-link`, иначе бот); объявление остаётся.
- [x] 1.0.7: «Торрент-клиенты мимо VPN» в раздельном туннелировании — включено
      по умолчанию, можно выключить: 31 известный торрент-клиент Windows
      (uTorrent, qBittorrent, BitTorrent, Transmission, Deluge, BitComet и др.)
      и Java внутри Zona идут напрямую, чтобы не грузить серверы.
      Там же «Местные сервисы мимо VPN», тоже включено: правило
      `RULE-SET,direct-sites,DIRECT` по встроенному набору `direct-sites` из
      шаблона подписки (банки, госуслуги, маркетплейсы); без набора правило
      не ставится.
- [x] 1.0.8: окно больше не чёрное на видеокартах Direct3D 10_0 (GeForce 9800 GT
      и ровесники): до старта движка запуск разрешает ANGLE OpenGL ES 3 на таком
      уровне (`ANGLE_FEATURE_OVERRIDES_ENABLED=allowES3OnFL100`), Impeller по-прежнему
      выключен; уровень Direct3D пишется в журнал строкой `renderer:`.
- [ ] 1.0.9: запуск больше не обрывается экраном «Отказано в доступе» (0x80070005),
      если антивирус или Windows не дают записать в реестр обработчик ссылок
      `nurconnect-win://`: регистрация необязательна, отказ пишется в журнал, а ключ
      `HKCU\Software\Classes\nurconnect-win` переписывается, только если его нет или он
      указывает на другую программу.
      Логи: «Поделиться логами» на Windows раньше молча ничего не делала (функция
      отправки есть только на Android) — теперь архив открывается выделенным в
      Проводнике и показывается путь к нему. «Захват логов» (журналы ядра) — в том же
      разделе «Логи и диагностика» главных настроек, с подсказкой, как собрать логи.
      Карточка профиля: ссылки провайдера, обновление и «⋯» чуть мельче (значок 19 вместо
      22, кнопка 28 вместо 32, без промежутков) — длинное название провайдера
      помещается; значок поддержки выровнен по центру строки (был ниже на 1,4).

Состояние тестов и пакетов: [первая сборка](first-build.md).

## Следующие этапы

1. Стенд Windows 11 x64 рядом с уже проверенным Windows 10 x64 22H2 (на нём же
   проверяется старая графика Direct3D 10_0); отдельная ARM64-сборка.
   При распространении прикладывать соответствующие исходники и инструкции.
2. QA-профиль: первая загрузка, HWID/лимит, обновление и кэш, подключение,
   TUN/proxy, отказ helper, гонки refresh/start/stop.
3. Установка рядом с FlClashX и stable/pre, обычный пользователь/UAC, трей,
   автозапуск, сон/смена сети, обновление/удаление и восстановление proxy.
4. Картинки установщика и оформление страниц настроек; полная инвентаризация
   лицензий assets.
5. Собственный ключ Ed25519, Authenticode и Windows CI. Приватные ключи держать
   вне репозитория. Унаследованные workflows до адаптации не включать.

## Проверки подписок

Parser не заменяет валидацию Core: YAML, age и конвертация share links остаются
в штатном потоке. Явный HWID refusal останавливает основную и резервную загрузки.
Staging/validate/rename и superseded guard сохранены. HTTP 403 сам по себе не
объявляется истечением подписки; пользовательские URL и core diagnostics не
выводятся в новом сообщении об ошибке. Полная проверка всех экспортов логов
на секреты — отдельная работа.
